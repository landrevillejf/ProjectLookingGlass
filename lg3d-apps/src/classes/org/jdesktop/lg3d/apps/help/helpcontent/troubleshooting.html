Troubleshooting and FAQ

The desktop will not start

  • No JDK 21. The launcher needs a JDK 21 toolchain. Set JAVA_HOME to a JDK 21 install and try again.
  • No display. The desktop renders into an X display. Make sure DISPLAY is set (it defaults to :0).
  • Gradle on a too-new JVM. Gradle 8.14 cannot run on Java 25+. Use the provided ./run-lg3d.sh, which pins the JDK 21 toolchain.

I only get a flat 2D desktop, not 3D

If Java 3D cannot initialize (no suitable graphics acceleration), the desktop falls back to the 2D desktop. This is expected on machines without 3D support. You can also choose it deliberately with -2 or -w.

Missing icons, wallpapers or the background chooser

These assets are assembled into a runtime resources tree before launch. If they are missing, reassemble it: 

./run-lg3d.sh -r
# or directly:
./gradlew :lg3d-core:runtimeResources

A window shows frozen or blank content

Hosted Swing panels are painted offscreen. If a panel was built with the platform (Synth/GTK) look and feel it can fail to paint into the offscreen buffer. The desktop installs the cross-platform Metal look and feel for hosted panels to avoid this; if you add your own hosted panel, install the hosted look and feel before constructing it.

Black screen in compositor mode (-x)

Compositor mode claims the display as its own window manager. Start it only when no other window manager holds the display, or the claim fails and you may see a black screen.

Performance is poor

  • Try the flat image background instead of the 3D model (drop -b).
  • Close windows you are not using; each live window is repainted into a texture.

Where are the logs?

The desktop configures java.util.logging from its logging.properties. Discovery and Start-Menu activity are logged at WARNING by default; raise the relevant loggers to FINE to see more detail when diagnosing a missing menu entry.
