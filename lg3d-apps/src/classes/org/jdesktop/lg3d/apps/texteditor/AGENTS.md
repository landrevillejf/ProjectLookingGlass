## Key components

- **AdvancedTextEditor** — thin 3D entry point; installs the hosted Metal look
  and feel (`TitledSwingWindow.installHostedLookAndFeel()`, never Synth — Synth
  widgets NPE when `SwingNode` paints them offscreen) and shows
  `AdvancedTextEditorPanel` in a `TitledSwingWindow`.
- **AdvancedTextEditorPanel** — the one Swing UI both desktops host (plain
  `JPanel`, no Java 3D, constructs headless): a `JTabbedPane` of `EditorTab`s, a
  toolbar, a `FindReplaceBar`, and a `CardLayout` centre that flips between the
  editor, the `RecentCard`, the `ExtensionsCard` and the `SettingsCard`. A
  package-private `AdvancedTextEditorPanel(false)` constructor disables prefs
  writes so tests never touch the user preference store.
- **EditorTab** — one document: a `DefaultStyledDocument` (JTextPane requires a
  `StyledDocument`) in an `EditorPane`, dirty tracking, single-step whole-text
  replace, caret geometry, smart keys, and a debounced re-highlight timer.
- **Engine (AWT-free, pure-String, headless-testable)** — `SyntaxHighlighter`
  (tokeniser + batch painter), `Languages`/`Language` (16 languages + Plain
  Text), `SearchEngine` (literal/regex find + replace, tolerant group expansion),
  `TextFileIO` (atomic write-to-temp + guarded read: size cap, BOM/charset
  sniff, binary reject), `SmartIndent`/`TextPositions`/`BracketMatcher`
  (indent + line/column + bracket pairing), `MergingUndoManager` (folds a typing
  burst into one undo step), `EditorSettings`/`EditorTheme` (persisted prefs +
  light/dark themes).
- **Extensions** — `TextEditorExtension` SPI discovered by `ExtensionRegistry`
  through `ServiceLoader`; built-ins via `META-INF/services`, third-party jars in
  `~/.lg3d/texteditor/extensions`; manager = `ExtensionBroker` (similar to web
  browser). Each provider declares a free-form `category()` (default `"General"`);
  the `ExtensionsCard` groups every contributed action under a bold, inert
  category header (curated order: Text, Code, Java/Kotlin, Web, Spring, Data,
  Encoding, Markdown, Analysis, General). Thirteen bundled providers:
  `BuiltinTextTools` ("Text Tools"), `CaseTools` (title/sentence/camel/snake/kebab
  on the selection), `CodeTools` (indent/outdent, drop-blank, dedup, reverse,
  number-lines), `FormatTools` (tabs↔spaces, LF/CRLF), `JavaDevTools` (sort
  imports, escape/unescape string literals, toggle `//` comments), `JvmBuildTools`
  (compile/run/debug the document with the real toolchain: `javac` + the JDK 11+
  single-file source launcher staged into a temp dir, a `-ea` crash-analysis run
  that reports `Debug: <exception> at Foo.java:<line>`, `kotlinc`/`kotlin` when
  installed, and a trailing `// ---- <tool> output ----` comment block that
  replaces itself per run; processes run on a virtual thread with EDT delivery,
  never on the UI, never on the user's file), `WebTools`
  (escape/unescape HTML entities, URL encode/decode), `SpringBootTools`
  (application.properties↔application.yml, sequences to `key[n]`; plus kebab-case
  key normalisation for Spring Boot 2+ relaxed binding and a `${...}` placeholder
  scan that appends a `# Referenced placeholders:` summary block), `JsonTools`
  (minify/pretty-print), `Base64Tools` (encode/decode the selection as Base64),
  `HashTools` (MD5/SHA-1/SHA-256 hex of the selection), `MarkdownTools` (toggle
  `**`/`*`/backtick emphasis and `-` bullet lists) and `TextStatsTool`
  (read-only word/char/line report). Each keeps its transforms as pure `String`
  statics for headless testing; grouping reorders the display only, so
  `runExtensionAction(index)` stays stable. A `ToolbarContribution` may carry an
  `accelerator` (a `KeyStroke` spec such as `"control alt A"`); the panel binds
  every *effective* accelerator (the user's rebound when one exists, else the
  declared default) on the shared `center` input map so the action runs straight
  from the editor, without opening the card (first action to claim a KeyStroke
  wins, later duplicates are skipped). Rebounds live in
  `EditorSettings.acceleratorOverrides` (contribution id → spec; a blank value
  unbinds) and are edited from the card's shortcut bar (Rebind grabs the next
  A-Z/0-9 + Ctrl/Alt/Shift/Meta, Clear unbinds) via `Host.getAccelerator` /
  `setAccelerator(index, spec)`. The card's left half lists installed extensions
  with Enable/Disable buttons plus a **Permissions** checkbox group
  (`Host.extensionInfos()` / `setExtensionEnabled(id, boolean)` / `permissionsFor(id)`
  / `setPermission(id, name, boolean)`; all default no-ops so third-party hosts
  stay source-compatible). Granting or revoking TOOLBAR adds or drops that
  extension's actions; toggling re-scans, rebuilds the flat action list and
  re-binds the accelerators. The panel also refreshes the extensions' document
  snapshot immediately before every action runs, so an action always sees the
  live text (a build action compiles what the user currently sees, not the file
  as opened).

## Roles

- **Architect** — The whole feature is self-contained in this package; no Java
  3D and no core-API dependency beyond the shared `TitledSwingWindow` host. The
  engine half (`SyntaxHighlighter`, `SearchEngine`, `TextFileIO`, `Languages`,
  `SmartIndent`, `BracketMatcher`, `MergingUndoManager`, `EditorSettings`) is
  pure `String`/NIO logic with **zero** Swing, so it is unit-testable off the
  EDT. The panel drives both desktops: 3D via `TitledSwingWindow`, 2D via
  `Desktop2DAppRegistry.PANEL_APPS` keyed on `AdvancedTextEditor`. Extensions
  cross the boundary only through the `EditorContext` interface — never by
  reaching into the panel.
- **Engineer / Developer** — Keep the engine Swing-free; keep Swing confined to
  the panel/tab/widgets. `JTextPane` needs a `StyledDocument`, so use
  `DefaultStyledDocument` and `getDefaultRootElement()` (not `getRootElement()`).
  Attribute-only edits (highlighting) must **never** dirty the tab or enter the
  undo history — guard them with the `loading` flag and `undo.discardAllEdits()`
  around construction/load. File writes go through `TextFileIO.save` (atomic
  temp-then-move); never `Files.writeString` directly. The extension point is
  the `TextEditorExtension` SPI + `META-INF/services` entry — add capabilities
  there, not by editing the panel. Jogamp packages only; obey the core UI/UX
  rulebook.
- **QA** — 24 headless JUnit 5 suites under
  `lg3d-apps/src/test/java/org/jdesktop/lg3d/apps/texteditor/` cover every
  engine class, all thirteen bundled extensions and all panel/widget surfaces (220
  tests): tokenisation, search &
  replace, atomic IO (BOM/charset/binary/oversize guards via `@TempDir`),
  smart-indent, bracket matching, the merging-undo clock seam, settings
  round-trip (including the `acceleratorOverrides` map), the extension SPI
  (category grouping, effective-accelerator binding via `isAcceleratorBound`,
  user rebound via `Host.setAccelerator`, the `ExtensionsCard` Enable/Disable and
  permission-grant `Host.setPermission` paths with the broker TOOLBAR gate), the
  JVM build tools (command builders, stack/exception parsing and output blocks
  are pure; actions drive a synchronous `Runner` seam so no test ever spawns a
  real process), the live-text refresh before
  `runExtensionAction`, tab lifecycle, and the find bar / status bar /
  recents / extensions cards. Build panels through
  `new AdvancedTextEditorPanel(false)`; file-chooser and `JOptionPane` paths are
  headless-guarded and intentionally unreachable in tests. For the 3D host use
  the in-JVM probe + internal screencapture (`lg3d-core/lgscreen-*.png`); a black
  capture under Wayland is not a defect.
- **Business Analyst** — A daily-driver utility: open, edit, find/replace and
  save text and source files from the desktop without a separate editor, with
  syntax highlighting for the common languages, recent-file recall, light/dark
  themes and a plug-in surface for text tools. Value = a trustworthy, fast,
  keyboard-friendly editor identical in both desktops.
- **Functional Analyst** — Spec this app as the *editor contract*: multi-tab
  open/save (atomic, guarded) with dirty tracking and safe close; regex + literal
  find/replace with live match counts and go-to-line; syntax highlighting for 16
  languages gated by a size cap; undo that merges a typing burst into one step;
  persisted settings (font, theme, indent, wrap, highlight) and a recent list;
  and a `TextEditorExtension` action surface. The engine classes behind each
  behaviour are implementation details.
- **Project Manager** — Commit scope `lg3d-apps`; the registration also touches
  `lg3d-core` (`Desktop2DAppRegistry.PANEL_APPS` mapping + registry test) and the
  generated icon in `lg3d-core` resources plus `GenerateAppIcons` in `lg3d-art` —
  call those out. Done = `./gradlew build` green + headless tests + a
  `./run-lg3d.sh` capture/log. Branch → PR against `main`; never commit to
  `main`.
- **UI/UX (3D & 2D)** — 3D: glassy `TitledSwingWindow` frame with the panel as
  the `SwingNode` content. 2D: the identical `AdvancedTextEditorPanel` in an MDI
  internal frame. Conventional editor chrome (tabs + toolbar + find bar + status
  line), never a click-cycling 3D idiom; keep both surfaces pixel-identical and
  honour the light/dark theme everywhere.
