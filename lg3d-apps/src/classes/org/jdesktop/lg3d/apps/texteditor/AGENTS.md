## App at a glance

## Key components

- **AdvancedTextEditor** — thin 3D entry point; installs the hosted Metal look
  and feel (`TitledSwingWindow.installHostedLookAndFeel()`, never Synth — Synth
  widgets NPE when `SwingNode` paints them offscreen) and shows
  `AdvancedTextEditorPanel` in a `TitledSwingWindow`.
- **AdvancedTextEditorPanel** — the one Swing UI both desktops host (plain
  `JPanel`, no Java 3D, constructs headless): a `JTabbedPane` of `EditorTab`s, a
  toolbar, a `FindReplaceBar`, and a `CardLayout` centre that flips between the
  editor, the `RecentCard`, the `ExtensionsCard` and the `SettingsCard`. The
  editor card sits inside a west/east `JSplitPane` with the `ProjectTreePanel`
  (a lazily-loaded file tree re-rooted on the project of the document being
  edited — `.git`/`pom.xml`/`build.gradle`/… walk-up — double-click opens a
  file) and inside a north/south `JSplitPane` whose south half is a bottom
  **`bottomTabs`** `JTabbedPane` (resize weight 0.78) holding four IDE surfaces:
  **Output** (the read-only monospaced `OutputConsole` where extension tool
  actions land their output, drop-oldest capped, `Clear` button), **Problems**
  (the `ProblemsPanel`, a sortable table of `Diagnostic`s), **Structure** (the
  `StructurePanel`, a `JTree` outline), and **Debug** (the `DebugPanel`,
  breakpoints + call stack + locals + a debug transcript). A debounced
  `analysisTimer` (idle 400 ms, restarted on every content edit and tab switch)
  fires `onDocumentChanged` for live-analysis extensions. A package-private
  `AdvancedTextEditorPanel(false)` constructor disables prefs writes so tests
  never touch the user preference store.
- **EditorTab** — one document: a `DefaultStyledDocument` (JTextPane requires a
  `StyledDocument`) in an `EditorPane`, dirty tracking, single-step whole-text
  replace, caret geometry, smart keys, and a debounced re-highlight timer. It
  also paints per-line diagnostics — a wavy `Highlighter.HighlightPainter`
  underline over each range plus a highest-severity gutter dot — via
  `setDiagnostics`/`clearDiagnostics`, and round-trips breakpoints to the
  gutter (`toggleBreakpoint`). A `setChangeListener` hook lets the panel observe
  content edits for debounced live analysis.
- **Engine (AWT-free, pure-String, headless-testable)** — `SyntaxHighlighter`
  (tokeniser + batch painter), `Languages`/`Language` (16 languages + Plain
  Text), `SearchEngine` (literal/regex find + replace, tolerant group expansion),
  `TextFileIO` (atomic write-to-temp + guarded read: size cap, BOM/charset
  sniff, binary reject), `SmartIndent`/`TextPositions`/`BracketMatcher`
  (indent + line/column + bracket pairing), `MergingUndoManager` (folds a typing
  burst into one undo step), `EditorSettings`/`EditorTheme` (persisted prefs +
  light/dark themes).
- **Extensions** — `TextEditorExtension` SPI discovered by `ExtensionRegistry`
  through `ServiceLoader`; built-ins via `META-INF/services`, third-party jars in
  `~/.lg3d/texteditor/extensions`; manager = `ExtensionBroker` (similar to web
  browser). Each provider declares a free-form `category()` (default `"General"`);
  the `ExtensionsCard` groups every contributed action under a bold, inert
  category header (curated order: Text, Code, Java/Kotlin, Web, Spring, Data,
  Encoding, Markdown, Analysis, General). Thirteen bundled providers:
  `BuiltinTextTools` ("Text Tools"), `CaseTools` (title/sentence/camel/snake/kebab
  on the selection), `CodeTools` (indent/outdent, drop-blank, dedup, reverse,
  number-lines), `FormatTools` (tabs↔spaces, LF/CRLF), `JavaDevTools` (sort
  imports, escape/unescape string literals, toggle `//` comments), `JvmBuildTools`
  (compile/run/debug the document with the real toolchain: `javac` + the JDK 11+
  single-file source launcher staged into a temp dir, a `-ea` crash-analysis run
  that reports `Debug: <exception> at Foo.java:<line>`, `kotlinc`/`kotlin` when
  installed; every run's output — success included — goes to the south
  `OutputConsole` through the FILE_IO-gated `EditorContext.showOutput`
  capability, and a legacy `// ---- <tool> output ----` comment block left in a
  document by earlier builds is stripped (WRITE) on the next action;
  `Clean Output` clears the console; processes run on a virtual thread with
  EDT delivery,
  never on the UI, never on the user's file), `WebTools`
  (escape/unescape HTML entities, URL encode/decode), `SpringBootTools`
  (application.properties↔application.yml, sequences to `key[n]`; plus kebab-case
  key normalisation for Spring Boot 2+ relaxed binding and a `${...}` placeholder
  scan that appends a `# Referenced placeholders:` summary block), `JsonTools`
  (minify/pretty-print), `Base64Tools` (encode/decode the selection as Base64),
  `HashTools` (MD5/SHA-1/SHA-256 hex of the selection), `MarkdownTools` (toggle
  `**`/`*`/backtick emphasis and `-` bullet lists) and `TextStatsTool`
  (read-only word/char/line report). Each keeps its transforms as pure `String`
  statics for headless testing; grouping reorders the display only, so
  `runExtensionAction(index)` stays stable. A `ToolbarContribution` may carry an
  `accelerator` (a `KeyStroke` spec such as `"control alt A"`); the panel binds
  every *effective* accelerator (the user's rebound when one exists, else the
  declared default) on the shared `center` input map so the action runs straight
  from the editor, without opening the card (first action to claim a KeyStroke
  wins, later duplicates are skipped). Rebounds live in
  `EditorSettings.acceleratorOverrides` (contribution id → spec; a blank value
  unbinds) and are edited from the card's shortcut bar (Rebind grabs the next
  A-Z/0-9 + Ctrl/Alt/Shift/Meta, Clear unbinds) via `Host.getAccelerator` /
  `setAccelerator(index, spec)`. The card's left half lists installed extensions
  with Enable/Disable buttons plus a **Permissions** checkbox group
  (`Host.extensionInfos()` / `setExtensionEnabled(id, boolean)` / `permissionsFor(id)`
  / `setPermission(id, name, boolean)`; all default no-ops so third-party hosts
  stay source-compatible). Granting or revoking TOOLBAR adds or drops that
  extension's actions; toggling re-scans, rebuilds the flat action list and
  re-binds the accelerators. The panel also refreshes the extensions' document
  snapshot immediately before every action runs, so an action always sees the
  live text (a build action compiles what the user currently sees, not the file
  as opened).
- **IDE extension SPI (Phase-0 groundwork)** — the additive capabilities that
  let live-analysis / debugger extensions plug in without breaking third-party
  source compatibility. `TextEditorPermission` gained **`DIAGNOSE`** (report
  per-line `Diagnostic`s; never mutates the document, so gated apart from
  `WRITE`) and **`DEBUG`** (drive the `DebugPanel` surface). `TextEditorExtension`
  gained a default **`onDocumentChanged(DocumentContext)`** hook (fired on the
  debounced edit signal). `DocumentContext` gained caret/selection accessors
  (`getCaretOffset`/`getCaretLine`/`getCaretColumn`/`getSelectionStart`/
  `getSelectionEnd`) via a wider constructor; the old constructor delegates with
  zeros. `EditorContext` gained `DIAGNOSE`-gated `reportDiagnostics`/
  `clearDiagnostics`/`showStructure` and `DEBUG`-gated `appendDebugOutput`/
  `setDebugState`/`showStack`/`showLocals`/`setBreakpoints` — each a silent no-op
  when its permission is not granted. All capability delegates are carried by the
  package-internal **`EditorSinks`** builder (so `EditorContext`/`ExtensionBroker`
  constructors stay clean and legacy constructors keep compiling via delegating
  `EditorSinks.legacy`). New immutable value records: **`Diagnostic`**
  (`path,line,col,endLine,endCol,Kind{ERROR,WARNING,INFO,HINT},message`) and
  **`StructureSymbol`** (`name,kind,line`). `ExtensionBroker` funnels
  opened/changed/saved through one shared permission-gated `dispatch` that
  isolates throwing extensions. The IDE chrome phases (live diagnostics,
  structure/navigation, JDI debugger, completion) build on this groundwork and
  each ships as its own extension provider off `main`. **Phase 1 is live:**
  `JavaDiagnosticsTools` (category `Java/Kotlin`, READ+DIAGNOSE, no toolbar
  actions) compiles the current document in memory with
  `ToolProvider.getSystemJavaCompiler()` + `DiagnosticCollector` (source never
  touches disk, class output dropped to a temp dir) and, for Kotlin, shells out
  to `kotlinc` from `PATH` and parses its `file:line:col: severity: msg` /
  `e:|w: file.kt: (L, C): msg` output; it triggers on
  open/changed/saved, runs on a virtual thread through a `Scheduler` seam, and a
  generation counter drops superseded results so typing never blocks and stale
  markers never paint. The `kotlinc` lookup, process runner and scheduler are
  injectable seams (every path headless-testable; no test spawns a real
  `kotlinc`), and a non-JVM or empty document clears stale diagnostics.
  **Phase 2 is live:** the SPI gained a `READ`-gated **`EditorContext.navigateTo(path, line)`**
  capability (carried by `EditorSinks.navigate`, delegated to the panel's
  `navigateForExtension` which selects the tab for the path and jumps the caret),
  and `JavaStructureTools` (category `Java/Kotlin`, READ+WRITE+DIAGNOSE+TOOLBAR,
  4 toolbar actions) publishes the Structure-tab outline by parsing the current
  document with the javac frontend (`JavacTask.parse()` + `Trees`/
  `SourcePositions` for exact lines; regex fallback for broken sources) and a
  documented best-effort regex/indent scan for Kotlin (no Kotlin AST exists in
  the JDK). Go-to-definition and find-occurrences resolve the identifier under
  the caret (string/char literals and comments masked out) and jump via
  `navigateTo`; rename replaces every whole-word occurrence in one
  `setFullText` write (single undo step) with the new name taken behind a
  `RenamePrompt` seam (production: a `JOptionPane` input; tests: a fake — no
  dialog is ever constructed); organize-imports drops unused single-type
  imports, dedupes and sorts the block (statics first, wildcards kept) leaving
  import-free files untouched.
  **Phase 3 is live:** a left-click on the line-number gutter toggles a
  breakpoint (`LineNumberGutter.installBreakpointClick`) and the SPI gained a
  `DEBUG`-gated **`EditorContext.getBreakpoints(path)`** read-back (carried by
  `EditorSinks.breakpointsFor`, delegated to the active tab's
  `breakpointLines()`). `JavaDebugTools` (category `Java/Kotlin`,
  READ+FILE_IO+DEBUG+TOOLBAR, 6 toolbar actions) drives the Debug tab: it
  stages the document, compiles with `javac` off the EDT (a `CompileRunner`
  seam), launches the *current* text as a child JVM with
  `-agentlib:jdwp=transport=dt_socket,server=y,suspend=y,address=127.0.0.1:<ephemeral>`
  (loopback-only; port reserved then released), and `JdiDebugBackend` attaches
  with `com.sun.jdi`, installs one breakpoint request per gutter line on
  class-prepare, and pumps breakpoint/step suspensions into the panel (state,
  call stack, `visibleVariables()` locals) while the child's merged
  stdout/stderr streams into the Output tab. Every `com.sun.jdi` call lives in
  the backend behind the `Backend`/`Session` seams — the state machine is
  headless-testable through those plus inline `Deliverer`/`AsyncRunner` seams —
  and every session end (user stop, VM death, editor close) detaches and
  `destroyForcibly()`s the child in a `finally` path. Kotlin debugging is
  refused politely (no supported line-table story without the compiler daemon).

## Roles

- **Architect** — The whole feature is self-contained in this package; no Java
  3D and no core-API dependency beyond the shared `TitledSwingWindow` host. The
  engine half (`SyntaxHighlighter`, `SearchEngine`, `TextFileIO`, `Languages`,
  `SmartIndent`, `BracketMatcher`, `MergingUndoManager`, `EditorSettings`) is
  pure `String`/NIO logic with **zero** Swing, so it is unit-testable off the
  EDT. The panel drives both desktops: 3D via `TitledSwingWindow`, 2D via
  `Desktop2DAppRegistry.PANEL_APPS` keyed on `AdvancedTextEditor`. Extensions
  cross the boundary only through the `EditorContext` interface — never by
  reaching into the panel.
- **Engineer / Developer** — Keep the engine Swing-free; keep Swing confined to
  the panel/tab/widgets. `JTextPane` needs a `StyledDocument`, so use
  `DefaultStyledDocument` and `getDefaultRootElement()` (not `getRootElement()`).
  Attribute-only edits (highlighting) must **never** dirty the tab or enter the
  undo history — guard them with the `loading` flag and `undo.discardAllEdits()`
  around construction/load. File writes go through `TextFileIO.save` (atomic
  temp-then-move); never `Files.writeString` directly. The extension point is
  the `TextEditorExtension` SPI + `META-INF/services` entry — add capabilities
  there, not by editing the panel. Jogamp packages only; obey the core UI/UX
  rulebook.
- **QA** — 31 headless JUnit 5 suites under
  `lg3d-apps/src/test/java/org/jdesktop/lg3d/apps/texteditor/` (and the `ext`-package
  `ExtensionBrokerDispatchTest`) cover every
  engine class, all sixteen bundled extensions and all panel/widget surfaces (304
  tests): tokenisation, search &
  replace, atomic IO (BOM/charset/binary/oversize guards via `@TempDir`),
  smart-indent, bracket matching, the merging-undo clock seam, settings
  round-trip (including the `acceleratorOverrides` map), the extension SPI
  (category grouping, effective-accelerator binding via `isAcceleratorBound`,
  user rebound via `Host.setAccelerator`, the `ExtensionsCard` Enable/Disable and
  permission-grant `Host.setPermission` paths with the broker TOOLBAR gate), the
  JVM build tools (command builders, stack/exception parsing are pure; actions
  drive a synchronous `Runner` seam so no test ever spawns a real process, and a
  fake `showOutput` delegate proves output lands in the console, never in the
  document), the south console's block grammar/line cap and the west project tree
  (project-root walk-up, lazy child loading, double-click-to-open), the
  live-text refresh before
  `runExtensionAction`, tab lifecycle, and the find bar / status bar /
  recents / extensions cards. Build panels through
  `new AdvancedTextEditorPanel(false)`; file-chooser and `JOptionPane` paths are
  headless-guarded and intentionally unreachable in tests. The Phase-0 IDE
  groundwork is covered by `IdeChromeTest` (the `Diagnostic`/`StructureSymbol`
  models, the widened `DocumentContext` caret + back-compat, the `DIAGNOSE`/`DEBUG`
  capability gates driven through `EditorSinks`, the gutter markers/breakpoints,
  `EditorTab` squiggle painting + breakpoint round-trip, the
  `ProblemsPanel`/`StructurePanel`/`DebugPanel` models, and the four-tab
  `bottomTabs` integration) and `ExtensionBrokerDispatchTest` (the
  `onDocumentChanged` dispatch carrying the caret, the READ gate, the WRITE-gated
  mutators, and per-extension exception isolation, using the package-private
  `ExtensionRegistry.seed` seam so no jar or filesystem IO runs). Phase-1 live
  diagnostics are covered by `JavaDiagnosticsToolsTest` (the pure `kotlinc`
  output parser in both formats, language detection, a real in-memory
  `javac` over broken and valid sources, and the analyze-to-report wiring driven
  through the synchronous `Scheduler` seam with a capturing `EditorSinks` —
  including generation-based staleness dropping, the no-compiler Kotlin
  degradation that spawns nothing, and the DIAGNOSE permission gate). Phase-2
  structure/navigation is covered by `JavaStructureToolsTest` (the AST outline
  with exact lines via a real in-memory parse, the regex fallback for broken
  sources, the Kotlin scan, caret-word extraction, string/comment-masked
  occurrence offsets, and the four actions driven end-to-end through capturing
  `EditorSinks` with a fake rename prompt and the READ/DIAGNOSE gates). Phase-3
  debugging is covered by `JavaDebugToolsTest` (the compile → launch → suspend →
  step → stop state machine driven entirely through fake `Backend`/`CompileRunner`
  seams with inline delivery so no test spawns a JVM, suspend-time output flush +
  the 200-line buffer, the DEBUG permission gate, the loopback-only
  `debugLaunchArgs`/`reserveLoopbackPort` builders, and one opt-in real-attach
  integration test guarded by `-Dlg3d.debug.integration=true`, off by default).
  For the 3D host use
  the in-JVM probe + internal screencapture (`lg3d-core/lgscreen-*.png`); a black
  capture under Wayland is not a defect.
- **Business Analyst** — A daily-driver utility: open, edit, find/replace and
  save text and source files from the desktop without a separate editor, with
  syntax highlighting for the common languages, recent-file recall, light/dark
  themes and a plug-in surface for text tools. Value = a trustworthy, fast,
  keyboard-friendly editor identical in both desktops.
- **Functional Analyst** — Spec this app as the *editor contract*: multi-tab
  open/save (atomic, guarded) with dirty tracking and safe close; regex + literal
  find/replace with live match counts and go-to-line; syntax highlighting for 16
  languages gated by a size cap; undo that merges a typing burst into one step;
  persisted settings (font, theme, indent, wrap, highlight) and a recent list;
  and a `TextEditorExtension` action surface. The engine classes behind each
  behaviour are implementation details.
- **Project Manager** — Commit scope `lg3d-apps`; the registration also touches
  `lg3d-core` (`Desktop2DAppRegistry.PANEL_APPS` mapping + registry test) and the
  generated icon in `lg3d-core` resources plus `GenerateAppIcons` in `lg3d-art` —
  call those out. Done = `./gradlew build` green + headless tests + a
  `./run-lg3d.sh` capture/log. Branch → PR against `main`; never commit to
  `main`.
- **UI/UX (3D & 2D)** — 3D: glassy `TitledSwingWindow` frame with the panel as
  the `SwingNode` content. 2D: the identical `AdvancedTextEditorPanel` in an MDI
  internal frame. Conventional editor chrome (tabs + toolbar + find bar + status
  line), never a click-cycling 3D idiom; keep both surfaces pixel-identical and
  honour the light/dark theme everywhere.
