## What

Wires the P5.4 `CellSnapshot` kernel into a real autosave, so the running world remembers where furniture was moved across a reboot instead of re-seeding from art and forgetting.

- **`WorldModel.revision()`** — a monotonic `AtomicLong` bumped by every add/graft/move/remove and never by a read, so an autosave can poll one number instead of keeping a listener list in sync.
- **`WorldAutosaver`** — the policy: when the revision has moved AND the world has settled for one quiet interval, it writes the snapshot. A failed write (disk full / read-only mount) is logged and leaves the world dirty so the next tick retries — an autosave must never take the server down over its own bookkeeping. The clock is an injected instant, so the whole judgement is unit-tested headlessly.
- **`WorldSnapshotService`** — the thin Spring bean (the only half that reads a real clock): `@PostConstruct` restore-on-boot, `@Scheduled` beat, `@PreDestroy` flush. **Off by default** — a blank `wonderland.server.snapshot.path` means no restore, no beat, no file, exactly the pre-P5.4 server. A torn snapshot on boot is logged and skipped, never fatal.
- **Roadmap honesty fix** — corrected the P5.4 bullet's claim that `PasscodeAuthenticator` is "called at the seam"; grep confirms it is a tested kernel only, deliberately left uncalled until the no-token deployment decision and a configured secret are settled.
