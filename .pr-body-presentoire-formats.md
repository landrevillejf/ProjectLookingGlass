## Presentoire: PowerPoint / LibreOffice compatibility + default Looking Glass deck

Presentoire now **opens and saves** Microsoft PowerPoint (`.pptx` and the legacy binary `.ppt`) and LibreOffice Impress (`.odp`) beside its own native `.zip` — round-trip import **and** export — and opens by default on a complete text/vector-only presentation of the **Looking Glass 3D and 2D** desktops. Everything flows through the one AWT-free `PresentoireModel`, so the 3D `Frame3D` and the 2D `PresentoirePanel` stay in lock-step.

Port and these subsequent modifications attributed to **Jean-Francois Landreville** (file headers, `@author`, commit sign-off). No version bump — it rides the current `[Unreleased]`.

### What's here

**New `presentoire.format` layer (headless):**
- `DeckFormat` — the four formats (`NATIVE .zip`, `PPTX`, `PPT`, `ODP`).
- `DeckCodecs` — `open(File)` sniffs the format by **magic bytes, not extension** (OLE2 → `.ppt`; ZIP → read the archive: `ppt/presentation.xml` → `.pptx`, a leading `mimetype` of `application/vnd.oasis.opendocument.presentation` → `.odp`, else a `<document>` root → native `.zip`; falls back to extension); `export(model, file, format)` writes any of the four.
- `NativeDeckCodec` — the native `.zip` **writer** the format never had (`content.xml` + `img/…`).
- `PptxDeckCodec` (POI XSLF) + `PptDeckCodec` (POI HSLF) — read and write.
- `OdpDeckCodec` — **pure-Java** OpenDocument read and write (`mimetype` first and uncompressed, `META-INF/manifest.xml`, `content.xml`, `Pictures/…`); no ODF library.
- `SlideGeometry` — fit-inside, aspect-preserving, centred map between an office page (4:3 / 16:9) and Presentoire's square `-0.1..0.1` slide, mirroring `SlideRenderer`'s bottom-left (text/list) and centre (image) anchoring so an import→export round trip lands where the renderer already draws.

**Model:** `PresentoireModel.of(...)` plus an `inlineImages` map carry pictures in memory (a deck is no longer tied to an on-disk `ZipFile`); `ModelColor.toHex` feeds the writers' solid fills; `demo()` now returns a **16-slide `LOOKING_GLASS_XML`** deck (a compiled-in constant — no binary, no Git LFS).

**UI:** the 2D panel routes open through `DeckCodecs`, adds a **Save As…** toolbar button and a multi-format file filter, and names the detected source format on its status line. The 3D `Presentoire.openDocument` routes through `DeckCodecs` too but stays **view-only** (no save affordance) — both faces read the same model, so content is identical.

**Build:** Apache POI (`poi-ooxml` + `poi-scratchpad`; `poi`/`xmlbeans`/`commons-*`/`log4j-api` transitive) added to the version catalog and re-resolved onto the hand-assembled `:lg3d-core` run classpath and into the release bundle (`presentoireLibs`). The ancient `ext/commons-io-1.0.jar` (2004; only fm3d uses it) predates `IOUtils.byteArray(int)` that POI needs, so the incubator **test** task now filters it off the runtime classpath by artifact name — the same pattern already used for `xercesImpl`/`mail`/`activation`, and the desktop run/release allow-lists already omit it.

### Fidelity (documented, intentional)

Only the Presentoire vocabulary is carried — text blocks, bullet lists and pictures. Themes, custom fonts, animations, tables, charts, grouped/rotated shapes and auto-fit are dropped on import and not emitted on export. Full PowerPoint/Impress visual fidelity is explicitly out of scope.
